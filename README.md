# School Fee Invoice Manager

A complete school fee invoicing web app: manage students, generate invoices with
automatic invoice numbers (`INV-2026-0001`), record payments, download/print
professional PDFs, track outstanding fees, and view reports.

Built with **Next.js 16** (App Router), **TypeScript**, **Tailwind CSS v4**,
**Supabase** (PostgreSQL + Auth), **React Hook Form + Zod**, **Recharts**, and
**jsPDF**.

## Features

- Admin authentication (sign in / create first account)
- Student directory with add / edit / delete and per-student fee history
- Invoice generation with dynamic fee items, discount, previous due roll-over,
  partial payments, and automatic invoice numbering (DB-level, concurrency safe)
- Invoice list with filters (month, status, academic year, search)
- Invoice detail page with totals, payment log, and action bar
- PDF download (jsPDF A4) and print-friendly view
- Fees ledger, dashboard with summary cards/recent activity
- Reports page with charts (bar + pie) and CSV export
- Parent search by name, phone or student ID
- Settings: school details, logo, invoice prefix/start number, currency

## Tech Stack

- Next.js 16 (Turbopack build), React 19, `src/` directory, `@/*` → `./src/*`
- Supabase: Postgres schema + Row Level Security + Auth (email/password)
- Server Actions for all data mutations
- Tailwind CSS v4 (CSS-first config via `src/app/globals.css`)

## Prerequisites

- Node.js 18.18+ (or 20+), npm

## Setup

### 1. Install dependencies

```bash
npm install
```

If your npm has peer-resolution issues on this machine, use:

```bash
npm install --legacy-peer-deps
```

### 2. Set up Supabase

1. Create a project at https://supabase.com
2. Open **SQL Editor** → New query, paste the contents of
   [`supabase/migrations/20260829200000_complete_school_fee_manager.sql`](supabase/migrations/20260829200000_complete_school_fee_manager.sql)
   and **Run**. This creates all tables, the invoice-number RPC, triggers and
   Row Level Security policies. This only needs to be done once.
   (For a readable one-file reference, `supabase/schema.sql` is identical.)

### 3. Configure environment variables

```bash
cp .env.example .env.local
```

Fill in the values from **Project Settings → API**:

```
NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-anon-key
```

### 4. Run the app

```bash
npm run dev
```

Open http://localhost:3000

### 5. Create the admin account

1. Go to the login page and open the **Create Account** tab.
2. Sign up with your email and password.
3. You are now signed in as the admin. Open **Settings** to configure the
   school name, address, invoice prefix, starting invoice number and currency
   before generating your first invoice.

## Project structure

- `supabase/` — database schema, RPC, triggers, RLS
  - `migrations/20260829200000_complete_school_fee_manager.sql` — canonical
    SQL to run in Supabase
  - `schema.sql` — identical, one-file reference
- `src/lib/`
  - `supabase/` — browser / server / middleware client factories
  - `actions.ts` — server actions (students, invoices, settings)
  - `validation.ts` — Zod schemas (input/output types for forms)
  - `types.ts` — shared TypeScript types
  - `pdf.ts` — jsPDF invoice generator
  - `settings.ts` — school & invoice settings accessors
- `src/app/`
  - `(dashboard)/` — protected pages: dashboard, students, invoices, fees,
    reports, parent search, settings
  - `login/page.tsx` — sign in / create account
  - `api/invoices/[id]/route.ts` — JSON feed used for PDF downloads
- `src/components/` — UI kit, invoice builder/document, charts, forms

## Notes

- Invoice numbers are generated by Postgres
  (`generate_invoice_number(p_year)`) so they never duplicate even with
  concurrent requests. Format: `PREFIX-YEAR-NNNN` (e.g. `INV-2026-0001`).
- The DB keeps invoice totals in sync via the `sync_invoice_totals` trigger
  whenever a payment is inserted.
- Row Level Security is enabled on every table; only authenticated users can
  read/write data, and `invoice_counters` is locked down so numbers can only be
  allocated through the RPC.
- The `middleware` file convention is deprecated in Next 16 but still works.
  To migrate to the new `proxy` convention run:
  `npx @next/codemod@canary middleware-to-proxy .`
